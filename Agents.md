
Règles à respecter absolument :

**Clareté**
- Le créateur de ce projet s'appelle Vassi, il a besoin que tout soit expliqué simplement et avec précision (max4live, code) mais sans métaphore.
- Il faut que chaque nouvelle fonctionnalité soit ré-évaluée et expliquée avec précision avant toute implémentation pour que Vassi puisse juger efficacement de la solution.
- Tout code écrit doit être commenté pour expliquer son fonctionnement au présent. Pas de mentions de ce qui a été modifié ou corrigé, le code n'est pas un historique. Les commentaires servent uniquement à décrire les comportement avec précision.


**Robustesse**
- Avant d'implémenter une nouvelle fonctionnalité, il faut impérativement faire une recherche internet pour vérifier les solutions utilisées pour ce problème précis afin de trouver les solutions les plus efficaces.

- Tout code écrit doit être review et testé de façon systématique. La robustesse du système est le critère le plus important. 


**Simplicité du code**
- Le code écrit doit être le plus simple possible et compréhensible même pour un développeur débutant. Pas de nom de variable complexe. 

- Le code doit être découpé en module ou composants, chaque fonction ne sert que pour une tâche précise. Les fichiers doivent rester relativement courts (pas plus de 300 lignes environ)
